# The vault

The company brain is an Obsidian vault. Its whole value is that what is written
in it is true and dated. Every rule below exists to protect that one property.

This folder holds the rules, the script that enforces them, the templates, and
three real notes as examples. The business facts themselves are not published.

## Structure

All content sits under one folder, split by kind:

| Folder | What goes in it |
| --- | --- |
| `self/` | The identity of the company. The hub every graph path leads back to. |
| `areas/` | Departments: the continuing functions. |
| `projects/` | Initiatives with an end date. |
| `concepts/` | Reusable definitions, not tied to a single fact or date. |
| `docs/` | Operating procedures and contractual text. |
| `entities/` | People, customers, suppliers, products, competitors, tools. |
| `data/` | Dated numeric snapshots: KPIs per year, price lists. |
| `outputs/` | Deliverables produced: analyses, backlogs, proposals. |
| `code/` | Notes about the internal software. |
| `sources/` | Raw material. Outside the quality gate. |
| `workspace/` | Scripts, work journal, scratch. Outside the content gate. |

`llms.txt` is the index of every real note, regenerated by
[`generate_llms_txt.py`](generate_llms_txt.py). It is the only source for names
to link: never write a `[[link]]` to something that does not appear there.

## The six rules

Enforced by [`quality_gate.py`](quality_gate.py) over the content folders. The
gate never edits anything. It only produces a report.

1. Complete frontmatter: `title`, `summary`, `tags`, `status`, `created`, `updated`.
2. Body at most 300 lines.
3. At least 3 outgoing wikilinks to notes that exist.
4. Zero broken links.
5. Zero orphans: every note has at least one incoming link. Index notes are exempt.
6. One connected component. No islands.

Rules 5 and 6 are the ones that do the real work. A fact nobody links to is a
fact nobody will find, and an island in the graph is a second brain nobody knows
about.

## The gate runs itself

[`gate_hook.py`](gate_hook.py) is registered as a `PostToolUse` hook in
[`settings.json`](settings.json), matching `Write|Edit`. After every write it
picks the right gate from the path of the file touched, and exits quietly unless
it finds something. When it finds something it exits with code 2 and prints the
report, so the agent sees its own mess and fixes it in the same turn.

`--workspace` is a reduced set for the journal and scratch notes: broken links,
frontmatter, and crust (`*.bak*`, stale DRAFTs, empty notes).

## Writing rules on top of the six

- **Absolute dates only**, `YYYY-MM-DD`. Never "today", never "last month". Read
  the real date from the system, do not infer it from context.
- **Every fact carries its source and the date it was checked.** "Verified on the
  public site on 2026-08-11" is the expected level. A number stated verbally and
  not documented is written down as a statement, not as a fact.
- **Gaps are written down.** Every note has a `## GAP` section holding what is
  not known. A declared hole is worth more than a note that looks complete.
- **Closed items stay written, with their date.** History is not deleted, so
  settled arguments do not get reopened.

## Source of truth

One question, one file. Which file wins is written down, because getting it
wrong has already cost work. Where two files disagree, the note says which one
is authoritative and why the other one is not.

The same rule governs the task board: **the board holds the state, the notes hold
the reasons.** A number is corrected in the note, never on the board. A priority
changes on the board, never in the note.

## Running the gate on your own vault

```
python quality_gate.py /path/to/vault
python quality_gate.py /path/to/vault --workspace
```

No dependencies. It prints how many notes it checked and either `OK, 0 errori`
or a report grouped by rule. Exit code is 0 either way; the hook is what turns a
report into a failure.
